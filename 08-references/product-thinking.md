# Product Thinking — คิดแบบ Product Owner
# ใช้เมื่อ: กำลังจะสร้าง product ของตัวเอง หรือต้องคิดในมุมธุรกิจ
# เป้าหมาย: คิดว่า "สร้างอะไรที่คนจ่ายเงินซื้อ" ไม่ใช่แค่ "สร้างอะไรที่ cool"

---

## Developer vs Product Owner Mindset

| Developer คิด | Product Owner คิด |
|---|---|
| "ใช้ tech อะไรดี?" | "ลูกค้าต้องการอะไร?" |
| "feature นี้เจ๋ง!" | "feature นี้สร้างรายได้ไหม?" |
| "ทำให้สมบูรณ์ก่อนปล่อย" | "ปล่อย MVP ไปทดสอบก่อน" |
| "ต้องมี X, Y, Z ทั้งหมด" | "ลูกค้าจะจ่ายเงินเพราะ feature ไหน?" |

---

## Checklist ก่อนสร้าง Product

### 1. Problem — ปัญหาที่แก้
- [ ] ปัญหาอะไร? ใครมีปัญหานี้?
- [ ] ปัญหานี้เจ็บปวดพอที่คนจะจ่ายเงินไหม?
- [ ] ตอนนี้เขาแก้ปัญหายังไง? (Excel? ทำมือ? ใช้ tool อื่น?)
- [ ] ทำไมวิธีปัจจุบันไม่ดีพอ?

### 2. Solution — วิธีแก้ของเรา
- [ ] solution ของเราดีกว่าของเดิมยังไง?
- [ ] MVP (เวอร์ชันเล็กสุด) ต้องมีอะไร?
- [ ] อะไรที่ "ดีพอ" สำหรับ v1?
- [ ] ลูกค้าใช้ solution เราแล้วชีวิตดีขึ้นยังไง?

### 3. Market — ตลาด
- [ ] ลูกค้าเป้าหมายคือใคร? (specific = เจาะจง)
- [ ] มีลูกค้าแบบนี้กี่ราย?
- [ ] มี competitor (คู่แข่ง) ไหม? เราต่างยังไง?
- [ ] ทำไมลูกค้าจะเลือกเราแทนคู่แข่ง?

### 4. Revenue — รายได้
- [ ] คิดเงินยังไง? (รายเดือน? ครั้งเดียว? freemium?)
- [ ] ราคาเท่าไร?
- [ ] ลูกค้ากี่รายถึงจะ cover ค่า server/เวลา?
- [ ] break-even (คุ้มทุน) ตอนไหน?

### 5. Execution — ทำจริง
- [ ] ใช้เวลาทำ MVP กี่สัปดาห์?
- [ ] ลูกค้ากลุ่มแรก (early adopter) หาจากไหน?
- [ ] จะ validate (ทดสอบ) ว่าคนต้องการจริงยังไง? ก่อนทำเยอะ
- [ ] ต้องลงทุนอะไรบ้าง? (เวลา, เงิน, เครื่องมือ)

## ตัวอย่าง: Product "Stock Management SaaS"

```
Product: ระบบจัดการ stock สำหรับร้านค้าเล็ก
ปัญหา: ร้านเล็กใช้ Excel นับ stock → ผิดบ่อย, oversell, ไม่ real-time
ลูกค้า: ร้านค้าปลีกเล็ก 1-5 สาขา, พนักงาน 3-10 คน
ทำไมต้องการ: ลด stock ผิดพลาด, รู้ stock real-time, ลด oversell
ต่างจากคู่แข่ง: ราคาถูกกว่า (ระบบใหญ่ราคาแพง), ง่ายกว่า (ไม่ต้อง training)
MVP: CRUD product + stock movement + dashboard + alert stock ต่ำ
ราคา: 499 บาท/เดือน (starter) — 999 บาท/เดือน (pro)
Validate: หาร้าน 5 ร้าน ให้ใช้ฟรี 1 เดือน → ดู feedback
Timeline: MVP 3 สัปดาห์ → validate 1 เดือน → launch
```

## Golden Rule

> "ถ้าลูกค้าไม่ยอมจ่ายเงิน = ปัญหาไม่ได้เจ็บปวดพอ"
>
> ทดสอบก่อนสร้าง ไม่ใช่สร้างแล้วค่อยหาคนใช้
