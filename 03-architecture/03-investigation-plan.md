# Investigation Plan — แผนสืบค้นปัญหาอย่างเป็นระบบ
# ใช้เมื่อ: มีปัญหาที่ต้องหาสาเหตุ แต่ยังไม่รู้ว่าพังตรงไหน
# หลัก: hypothesis → evidence → validate → narrow down → fix

---

## Flow การ Investigate

```
อาการ (Symptom)
    │
    ▼
ตั้งสมมติฐาน (Hypothesis) — "น่าจะเป็นเพราะ..."
    │
    ▼
หา Evidence — "ถ้าจริง จะเห็นอะไร?"
    │
    ▼
ทดสอบ (Validate) — "เจอจริงไหม?"
    │
    ├── ใช่ → พบ Root Cause → แก้
    │
    └── ไม่ใช่ → ตั้งสมมติฐานใหม่ → วนลูป
```

## ตัวอย่าง: Stock ตัดเกิน

### 1. Symptom
```
ปัญหา: ลูกค้าแจ้งว่าสินค้า A เหลือ 10 แต่ระบบแสดง 0
เริ่มเกิด: วันจันทร์ หลัง deploy feature ขาย bundle
เกิดทุกครั้ง: ไม่ — เฉพาะสินค้าที่มี bundle
```

### 3. Hypothesis

| # | สมมติฐาน | ถ้าจริง → | วิธีทดสอบ | ผล | ใช่? |
|---|---|---|---|---|---|
| 1 | Bundle ตัด stock ซ้ำ (ตัดทั้ง bundle + แต่ละชิ้น) | stock ลดมากกว่าที่ขายจริง | ดู stock_transactions table | ลด 2 ครั้งต่อ 1 order | ✅ |
| 2 | Race condition | เกิดเฉพาะตอนขายพร้อมกัน | ทดสอบ 2 คนซื้อพร้อมกัน | ไม่เกิด | ❌ |

### 4. Root Cause
```
สาเหตุ: code ตัด stock ทั้งในระดับ bundle item + individual item ซ้ำ
ทำไม: feature bundle ไม่ได้เช็คว่า item อยู่ใน bundle หรือเปล่า
```
