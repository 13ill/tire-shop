# System Mapping — วาดแผนที่ระบบ
# ใช้เมื่อ: ผ่าน Gate 1 แล้ว → ต้องเข้าใจว่าระบบนี้อยู่ตรงไหนในภาพใหญ่
# เป้าหมาย: รู้ว่า upstream/downstream/dependency คืออะไร ก่อนลงมือทำ

---

## ทำไมต้องทำ System Mapping?

เพราะทุกระบบไม่ได้อยู่ตัวเดียว — มันเชื่อมกับระบบอื่น:
```
ถ้าแก้ระบบ A โดยไม่รู้ว่า B พึ่งพา A อยู่ → B พังด้วย
```

ตัวอย่าง:
```
ถ้าแก้ระบบ stock (เปลี่ยน API response format)
→ POS ที่ดึง stock อยู่ก็จะพัง (เพราะ format เปลี่ยน)
→ ลูกค้าขายของไม่ได้
```

---

## คำศัพท์สำคัญ

| คำ | หมายความว่า | ตัวอย่าง Stock/POS |
|---|---|---|
| upstream | ระบบที่อยู่ "ก่อน" เรา — ส่งข้อมูล/request เข้ามา | POS ส่งรายการขายมาให้ stock ตัดจำนวน |
| downstream | ระบบที่อยู่ "หลัง" เรา — รับข้อมูลจากเรา | ระบบบัญชีดึง stock ไปคำนวณต้นทุน |
| dependency | สิ่งที่ระบบเราต้องพึ่งพา — ถ้ามันพัง เราพัง | database, Redis cache, third-party API |
| shared service | service ที่หลายระบบใช้ร่วมกัน | ระบบ auth (login) ที่ทุกระบบใช้ |
| data flow | ทิศทางที่ข้อมูลไหล | สินค้าเข้าคลัง → stock เพิ่ม → POS เห็น |

## 6. วาดภาพ System Map (ให้ AI ช่วยวาดได้)

```
[upstream 1] ──→ [ระบบเรา] ──→ [downstream 1]
[upstream 2] ──→ [ระบบเรา] ──→ [downstream 2]
                     │
                     ├── พึ่งพา [dependency 1]
                     └── พึ่งพา [dependency 2]
```

### ตัวอย่าง: ระบบ Stock

```
[POS] ─────────→ [Stock System] ──→ [ระบบบัญชี]
[Admin Panel] ──→ [Stock System] ──→ [Report Dashboard]
[Supplier App] ─→ [Stock System] ──→ [Alert System (LINE)]
                        │
                        ├── พึ่งพา PostgreSQL
                        ├── พึ่งพา Redis (cache stock count)
                        └── พึ่งพา Auth Service (login)
```
