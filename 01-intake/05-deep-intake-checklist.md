# Deep Intake Checklist — Gate 1 แบบเข้มข้น
# ไม่ใช่แค่ถาม "ทำไปทำไม?" แต่ต้องเจาะลึกทุกมิติ
# AI ต้อง: ถาม + วิเคราะห์จาก domain knowledge + เสนอสิ่งที่อาจขาด

---

## ส่วน A: เป้าหมาย + Context (เหมือนเดิม แต่เข้มขึ้น)

- [ ] ปัญหาที่แก้คืออะไร? (เจาะจง ไม่ใช่กว้างๆ)
- [ ] ทำเพื่อใช้เอง / ขายลูกค้า / ทำเป็น product?
- [ ] success วัดจากอะไร? (ตัวเลข/พฤติกรรม)
- [ ] ใครใช้? กี่คน? role อะไรบ้าง?
- [ ] budget / เวลาที่มี?
- [ ] deadline จริงหรือเทียม?

---

## ส่วน B: ข้อมูลดั้งเดิม (Existing Data & Legacy) ⭐ สำคัญมาก

- [ ] **ตอนนี้ทำงานยังไง?** (มือ? Excel? ระบบเดิม? กระดาษ?)
- [ ] **มีข้อมูลเก่าไหม?** → format อะไร? (Excel, Access, MySQL, กระดาษ)
- [ ] **ข้อมูลเก่ามีอะไรบ้าง?**
  - รายการสินค้า กี่รายการ? กี่หมวด?
  - ข้อมูลลูกค้า กี่ราย?
  - ประวัติการขาย/ซ่อม มีไหม?
  - ยอด stock ปัจจุบัน?
- [ ] **ต้อง migrate (ย้าย) ข้อมูลเก่าเข้าระบบใหม่ไหม?**
- [ ] **มีระบบอื่นที่ใช้อยู่ไหม?** (บัญชี, LINE, e-commerce)
- [ ] **ข้อมูลไหนที่ห้ามหาย?** (critical data)

---

## ส่วน C: รายการสินค้า/บริการ (Item & Service Details) ⭐

- [ ] **สินค้ามีกี่หมวดหมู่?** แต่ละหมวดมีอะไร?
- [ ] **สินค้ามีกี่ SKU โดยประมาณ?** (10? 100? 1000? 10000?)
- [ ] **สินค้ามี variant ไหม?** (size, color, brand, รุ่น)
- [ ] **มีบริการ (service) ด้วยไหม?** → รายการอะไรบ้าง?
- [ ] **ราคาเป็นแบบไหน?**
  - ราคาตายตัว (fixed)?
  - ราคาตามขนาด/ชนิด?
  - ราคาตามชั่วโมง?
  - ราคาต่อรองได้?
  - มี tier (ส่ง/ปลีก) ไหม?
- [ ] **หน่วยนับ (unit) เป็นอะไร?** (ชิ้น, เส้น, ลิตร, งาน)
- [ ] **มี serial number / lot / วันหมดอายุ ไหม?**
- [ ] **มี minimum stock (จุดสั่งซื้อ) ไหม?**

## ส่วน D: Workflow ปัจจุบัน (Current Process)

- [ ] **ลูกค้ามาถึงร้าน → เกิดอะไรขึ้นทีละขั้น?**
  ```
  ตัวอย่าง: ร้านยาง
  1. ลูกค้ามา → บอกปัญหา/ต้องการอะไร
  2. พนักงานเช็ค → เสนอราคา
  3. ลูกค้า OK → เปิด job ซ่อม / ขายสินค้า
  4. ช่างทำงาน (ถ้าเป็นซ่อม)
  5. เสร็จ → คิดเงิน → ออกบิล
  6. ลูกค้าจ่าย → จบ
  ```
- [ ] **จุดไหนที่เป็นปัญหาตอนนี้?** (ช้า, ผิดพลาด, ลืม)
- [ ] **มี job ที่ต้องรอหลายวันไหม?** (นัดกลับมา, สั่งอะไหล่)
- [ ] **ใครตัดสินใจเรื่องราคา?** (owner เท่านั้น? หรือพนักงานได้?)

## ส่วน E: Domain Analysis — AI วิเคราะห์จากระบบทั่วไป ⭐

**AI ต้องทำ:** เมื่อรู้ว่าเป็นธุรกิจประเภทไหน → วิเคราะห์จาก pattern ทั่วไปแล้วเสนอกลับ

```
เมื่อผู้ใช้บอกว่า: "ร้านขายยาง + อะไหล่ + ซ่อมบำรุง + งานจิปาถะ"

AI ต้องวิเคราะห์:
ธุรกิจนี้เป็นแบบ "Retail + Service Hybrid" — มีทั้งขายของ + ให้บริการ

ระบบทั่วไปสำหรับธุรกิจแบบนี้มักมี:
┌───────────────────────────────────────────────┐
│ Modules ที่มักต้องมี                           │
├───────────────────────────────────────────────┤
│ ✅ POS (ขาย)                                  │
│ ✅ Stock (คลังสินค้า)                          │
│ ✅ Service Jobs (งานซ่อม/บริการ)              │
│ ✅ Products & Services (รายการสินค้า+บริการ)  │
│ ✅ Customers + Vehicles (ลูกค้า+รถ)          │
│ ⚡ Quotation (ใบเสนอราคา)                    │
│ ⚡ Invoice/Receipt (ใบเสร็จ/ใบกำกับภาษี)     │
│ ⚡ Supplier + Purchase Order (สั่งซื้อ)       │
│ 💡 Booking/Queue (นัดหมาย/คิว)               │
│ 💡 Warranty tracking (การรับประกัน)           │
│ 💡 Commission (ค่าคอมพนักงาน)                │
└───────────────────────────────────────────────┘
✅ = มักต้องมี  ⚡ = ควรมี  💡 = Nice to have

แล้วถามกลับ: "จากลิสต์นี้ อะไรที่ต้องมี / ไม่ต้องมี / ทำทีหลัง?"
```

## ส่วน F: เงื่อนไขพิเศษ (Business Rules)

- [ ] **ส่วนลด** — มีกี่แบบ? (ลูกค้าเก่า, ซื้อเยอะ, โปรโมชัน?)
- [ ] **ภาษี** — ต้องคำนวณ VAT ไหม? ออกใบกำกับภาษีไหม?
- [ ] **การชำระเงิน** — รับวิธีไหนบ้าง? (เงินสด, โอน, เครดิต, ผ่อน?)
- [ ] **การรับประกัน** — สินค้า/บริการมีประกันไหม? กี่วัน?
- [ ] **เงื่อนไขราคาพิเศษ** — ราคาส่ง vs ปลีก? ลูกค้า VIP?
- [ ] **เอกสาร** — ต้องออกเอกสารอะไรบ้าง? (ใบเสร็จ, ใบเสนอราคา, ใบส่งของ?)

---

## ส่วน G: ข้อจำกัด + ความต้องการพิเศษ

- [ ] **ต้องใช้ offline ได้ไหม?** (internet ร้านเสถียรไหม?)
- [ ] **อุปกรณ์ที่ใช้** — PC? Tablet? มือถือ? เครื่อง print?
- [ ] **Barcode/QR** — สินค้ามี barcode ไหม? ต้อง scan ไหม?
- [ ] **ภาษา** — ไทยอย่างเดียว? หรือ EN ด้วย?
- [ ] **จำนวน user** — กี่คนใช้พร้อมกัน?
- [ ] **ความปลอดภัย** — ใครเห็นอะไรได้? (เจ้าของเห็นหมด vs พนักงานเห็นบางส่วน)

## ส่วน H: Requirement Discovery — AI ต้อง proactive เสนอ ⭐⭐⭐

```
กฎสำคัญ:
AI ห้ามรอให้ผู้ใช้คิด requirement เอง
AI ต้องดึง domain knowledge มาเสนอ requirement ที่ "ระบบประเภทนี้ควรมี"
แล้วให้ผู้ใช้เลือก: ต้องมี / ไม่ต้อง / ทำทีหลัง
```

### วิธีทำ:

1. **ระบุประเภทธุรกิจ** — เช่น "Retail + Service Hybrid"
2. **ดึง requirement มาตรฐานของธุรกิจประเภทนั้น** โดยครอบคลุมทุกมิติ:

### มิติที่ต้องครอบคลุม (ห้ามข้าม):

#### H1: เอกสาร + การเงิน (Documents & Financial)
- [ ] ใบเสนอราคา (Quotation)
- [ ] ใบแจ้งหนี้ (Invoice)
- [ ] ใบเสร็จรับเงิน (Receipt)
- [ ] ใบกำกับภาษี (Tax Invoice)
- [ ] ใบส่งของ (Delivery Note)
- [ ] ใบสั่งงาน (Work Order)
- [ ] เงินเชื่อ / ค้างจ่าย (Credit/AR)
- [ ] เงินมัดจำ (Deposit)
- [ ] คืนสินค้า / Refund
- [ ] ยกเลิกบิล (Void)
- [ ] Split payment (จ่ายหลายวิธีในบิลเดียว)

#### H2: การจัดซื้อ + Supplier (Procurement)
- [ ] ข้อมูล Supplier
- [ ] ใบสั่งซื้อ (Purchase Order)
- [ ] รับสินค้าเข้า (Goods Received Note)
- [ ] ราคาทุน (Cost price) ต่อ supplier
- [ ] ประวัติการสั่งซื้อ

#### H3: Stock ละเอียด (Inventory Details)
- [ ] Low stock alert (แจ้งเตือนของใกล้หมด)
- [ ] Stock reservation (จองของไว้สำหรับ job)
- [ ] Stock count / audit (ตรวจนับ เทียบระบบ)
- [ ] Stock loss / shrinkage (สินค้าหาย/เสียหาย)
- [ ] Stock valuation (คำนวณมูลค่าสต็อก FIFO/ค่าเฉลี่ย)
- [ ] Storage locations (จุดเก็บ: คลัง/ชั้น/ตำแหน่ง)
- [ ] Stock transfer (ย้ายระหว่าง location)
- [ ] Batch/Lot tracking
- [ ] วันหมดอายุ (Expiry)

#### H4: POS หน้าร้าน (Point of Sale Operations)
- [ ] เปิด-ปิดกะ (Shift management)
- [ ] เงินทอน / เงินในลิ้นชัก (Cash drawer)
- [ ] ยอดสรุปประจำวัน (Daily closing / Z-report)
- [ ] Hold / Park bill (เก็บบิลไว้ก่อน)
- [ ] Barcode scan
- [ ] พิมพ์ใบเสร็จ (Receipt printer — thermal)
- [ ] หน้าจอลูกค้า (Customer display)

#### H5: งานบริการ ละเอียด (Service Operations)
- [ ] ใบสั่งงาน (Work Order) — print ให้ช่าง
- [ ] BOM ต่อ job (อะไหล่ที่ใช้ → ตัด stock อัตโนมัติ)
- [ ] เวลาเข้า-ออกของรถ/งาน
- [ ] ผูกหลาย job กับ 1 visit
- [ ] Follow up หลังซ่อม (แจ้งเตือน)
- [ ] ค่าแรงแยกต่างหาก
- [ ] ประมาณการซ่อม vs ค่าจริง

#### H6: ลูกค้า ละเอียด (Customer Management)
- [ ] ประวัติการซื้อ (Purchase history)
- [ ] กลุ่มลูกค้า (ปลีก/ส่ง/VIP/ขาจร)
- [ ] สมาชิก / สะสมแต้ม (Loyalty)
- [ ] แจ้งเตือนลูกค้า (LINE/SMS — งานเสร็จ, โปรโมชัน)
- [ ] บันทึกข้อมูลรถของลูกค้า (ยี่ห้อ/รุ่น/ทะเบียน/ขนาดยาง)

#### H7: บริหารร้าน (Business Management)
- [ ] รายรับ-รายจ่ายร้าน
- [ ] Commission ช่าง/พนักงาน
- [ ] เข้างาน-ออกงาน (Time attendance)
- [ ] Reports (ยอดขาย, กำไร, สินค้าขายดี, stock aging)
- [ ] Dashboard owner (ภาพรวมร้าน)

#### H8: Infrastructure / Non-functional
- [ ] Multi-device (หลายเครื่องพร้อมกัน)
- [ ] Offline capability
- [ ] Sync strategy
- [ ] Backup / data recovery
- [ ] Print support (thermal, A4)
- [ ] Mobile responsive (มือถือช่าง)
- [ ] Role-based access (owner เห็นหมด, staff เห็นบางส่วน)
- [ ] Audit log (ใครทำอะไร เมื่อไร)

## สรุป: AI ต้องทำ 4 อย่างใน Gate 1

```
1. ถาม — ถามคำถามจาก checklist ส่วน A-G (เลือกที่เกี่ยวข้อง)
2. ขุด — ดึง requirement จาก domain knowledge ทุกมิติ H1-H8 
         (ห้ามรอให้ผู้ใช้คิดเอง ต้องเสนอก่อน)
3. จัดกลุ่ม — แต่ละ req ให้ผู้ใช้เลือก: ✅ ต้องมี / 💡 ทำทีหลัง / ❌ ไม่ต้อง
4. Confirm — สรุป scope ทั้งหมด → รอ confirm → ห้ามไปต่อจนกว่าจะได้
```
