# Requirement Clarification — คำถามที่ต้องถาม Owner เพิ่ม
# ใช้เมื่อ: ยังมีข้อมูลไม่ครบ ต้องถามกลับ owner/ลูกค้า
# เคล็ดลับ: copy คำถามจากที่นี่ไปถาม owner ตรงๆ ได้เลย

---

## วิธีถาม owner อย่างมืออาชีพ

### หลักการ
- ถามเป็นชุด (3-5 คำถาม) ไม่ใช่ถามทีละข้อ → ลด round trip
- บอกเหตุผลว่าทำไมถาม → owner จะตอบได้ตรงประเด็น
- ใช้ภาษาเข้าใจง่าย → ไม่ใช้ศัพท์ tech กับ owner

### ตัวอย่างวิธีเปิด

```
"ก่อนเริ่มทำ ขอถามเพิ่มเพื่อให้ได้งานที่ตรงที่สุดนะครับ/ค่ะ
มี 5 ข้อครับ/ค่ะ:"
```

## ชุดคำถามสำเร็จรูป — แยกตามสถานการณ์

### A. เมื่อได้ Task ใหม่ (ข้อมูลยังไม่ชัด)

```
1. เป้าหมายหลักของงานนี้คืออะไรครับ/ค่ะ? (อยากได้ผลลัพธ์แบบไหน)
2. ถ้าเสร็จแล้ว จะวัดว่าสำเร็จจากอะไร?
3. ตอนนี้ทำยังไงอยู่? มีปัญหาอะไร?
4. มีตัวอย่างหรือ reference ไหมครับ/ค่ะ? (ระบบที่ชอบ, screenshot, etc.)
5. deadline คือเมื่อไร? มีเหตุผลเฉพาะไหม?
```

### B. เมื่อ Requirement ไม่ตรงกัน (ambiguous = กำกวม)

```
1. ขอ confirm ว่าที่เข้าใจถูกไหมครับ/ค่ะ: [สรุปที่เข้าใจ]
2. ตรงนี้หมายความว่า A หรือ B?
3. ถ้าเป็น A จะได้ [ผลลัพธ์ A] / ถ้าเป็น B จะได้ [ผลลัพธ์ B] — ต้องการแบบไหน?
4. มี case ที่เป็นข้อยกเว้นไหม?
5. priority ระหว่าง X กับ Y ตัวไหนสำคัญกว่า?
```

### C. เมื่อ Scope ไม่ชัด (อาจบานออก)

```
1. Phase แรกต้องมีอะไรบ้างที่ "ต้องมี"?
2. อะไรที่ "อยากได้แต่ทีหลังก็ได้"?
3. อะไรที่ "ไม่ต้องมีในครั้งนี้"?
4. ถ้าต้องเลือก 3 features ที่สำคัญที่สุด จะเลือกอะไร?
5. budget / เวลามีจำกัดแค่ไหน?
```

### D. เมื่อเป็น Bug / ปัญหา

```
1. ปัญหานี้เริ่มเกิดตั้งแต่เมื่อไร?
2. เกิดทุกครั้งหรือบางช่วง? มีเงื่อนไขอะไร?
3. มี screenshot / error message / log ไหม?
4. ถ้าปกติ ควรทำงานยังไง? (expected behavior)
5. ตอนนี้ทำงานผิดยังไง? (current behavior)
6. กระทบลูกค้า/ผู้ใช้กี่คน?
7. เคยเกิดมาก่อนไหม? แก้ยังไง?
8. มีอะไรเปลี่ยนก่อนหน้าที่จะเกิดปัญหาไหม? (deploy ใหม่, update อะไร)
```

### E. เมื่อต้องประเมินราคา/เวลา

```
1. ต้องการ quality ระดับไหน? (prototype ทดลอง vs production ใช้จริง)
2. มี deadline ตายตัวไหม? เพราะอะไร?
3. budget range อยู่ประมาณเท่าไร?
4. ต้อง maintain (ดูแลต่อ) หลังส่งมอบไหม?
5. มีฟีเจอร์ไหนที่ตัดได้ถ้า budget/เวลาไม่พอ?
```

## ถ้ากลัวถาม — อ่านตรงนี้

### ทำไมถามเป็นเรื่องดี:
- owner **ชอบคนถาม** เพราะแสดงว่าคิดลึก ใส่ใจงาน
- ถาม 5 นาที **ประหยัดเวลา 5 ชั่วโมง** ที่จะต้องทำใหม่
- ถ้าไม่ถาม แล้วทำผิด → owner จะไม่พอใจมากกว่าถามเยอะ

### เทคนิค:
- ถามเป็นชุด → ไม่รู้สึกว่าถามเยอะ
- ขึ้นต้นด้วย "เพื่อให้งานออกมาตรงที่สุด" → owner เข้าใจว่าทำไมถาม
- ให้ทางเลือก → owner ตอบง่ายกว่าคิดเอง
  เช่น "ต้องการแบบ A หรือ B?" ดีกว่า "ต้องการยังไง?"
