# Deep Requirement Intake — ถาม Requirement เจาะลึก
# ใช้เมื่อ: ผ่าน Goal Clarification แล้ว → ต้องเข้าใจรายละเอียดก่อนเริ่มทำ
# กฎ: ข้อไหนตอบไม่ได้ = ต้องถามกลับผู้ให้งาน ห้ามเดา

---

## A. Scope & Boundaries — ขอบเขตงาน

| # | คำถาม | หมายความว่า | ตัวอย่าง Stock/POS | คำตอบ |
|---|---|---|---|---|
| 1 | scope ครอบคลุมอะไร? | งานนี้ต้องทำอะไรบ้าง | "เพิ่ม/ลด stock + ดู report + alert เมื่อต่ำ" | |
| 2 | อะไรที่ **ไม่อยู่** ใน scope? | ชัดเจนว่าจะไม่ทำอะไร | "ไม่รวมระบบบัญชี, ไม่รวมระบบ shipping" | |
| 3 | phase แรกต้องทำอะไร? | MVP (เวอร์ชันเล็กสุดที่ใช้ได้) | "แค่เพิ่ม/ลด + ดู stock คงเหลือ" | |
| 4 | มีงานที่ต้องทำก่อนไหม? | prerequisite (สิ่งที่ต้องเสร็จก่อน) | "ต้องมี product master ก่อน" | |
| 5 | มี deadline? เพราะอะไร? | เร่งจริงหรือเร่งเทียม | "2 สัปดาห์ เพราะร้านเปิดใหม่" | |

---

## B. ข้อมูลที่ต้องรู้ — Deep Dive

| # | คำถาม | หมายความว่า | ตัวอย่าง | คำตอบ |
|---|---|---|---|---|
| 1 | expected behavior คืออะไร? | ถ้าทำเสร็จ ต้องเห็นอะไร | "กดขาย → stock ลดทันที" | |
| 2 | current behavior คืออะไร? | ตอนนี้ทำงานยังไง / มีปัญหาอะไร | "ตอนนี้ใช้ Excel นับ stock → ผิดบ่อย" | |
| 3 | เคยเกิดมาก่อนไหม? | ดู pattern ปัญหาซ้ำ | "เดือนก่อน stock ผิด 15 รายการ" | |
| 4 | มีตัวอย่าง case ไหม? | evidence (หลักฐาน) จริง | "screenshot Excel ที่ stock ติดลบ" | |
| 5 | เกิดทุกครั้ง หรือบางช่วง? | narrow down (จำกัดขอบเขตปัญหา) | "ผิดตอน peak hour เพราะขายพร้อมกันหลายคน" | |
| 6 | user กี่คนที่ใช้? | ขนาด + performance requirement | "พนักงาน 5 คน ใช้พร้อมกัน" | |
| 7 | มี data/environment ที่ทดสอบได้ไหม? | สามารถ reproduce (จำลองปัญหา) ได้ | "มี Excel ข้อมูลจริง 500 รายการ" | |

## C. Constraints — ข้อจำกัด

| # | คำถาม | หมายความว่า | ตัวอย่าง | คำตอบ |
|---|---|---|---|---|
| 1 | budget มีจำกัดไหม? | เลือก solution ที่ราคาเหมาะ | "ไม่เกิน 500 บาท/เดือน สำหรับ server" | |
| 2 | tech stack ต้องเป็นอะไร? | ข้อจำกัดทาง technology | "ใช้ Node.js เพราะทีมถนัด" หรือ "เลือกได้เลย" | |
| 3 | มี legacy (ระบบเดิม) ที่ห้ามแก้ไหม? | เข้าใจ constraints | "ระบบบัญชีเดิมใช้ MySQL ต้องเชื่อมได้" | |
| 4 | มี compliance/regulation ไหม? | กฎหมาย/ข้อบังคับ | "ต้องเก็บ log การเปลี่ยน stock 7 ปี" | |
| 5 | performance requirement เป็นยังไง? | ขนาด + ความเร็ว | "รองรับ 5 คนพร้อมกัน, โหลดไม่เกิน 3 วินาที" | |

---

## D. Edge Cases — กรณีพิเศษที่อาจพัง

| # | คำถาม | หมายความว่า | ตัวอย่าง | คำตอบ |
|---|---|---|---|---|
| 1 | ถ้า input ผิดรูปแบบ? | error handling (จัดการข้อผิดพลาด) | "ใส่จำนวน stock เป็นตัวอักษรแทนตัวเลข" | |
| 2 | ถ้าหลายคนทำพร้อมกัน? | concurrency (การทำงานพร้อมกัน) | "2 คนตัด stock สินค้าเดียวกัน → stock ติดลบ?" | |
| 3 | ถ้า downstream (ระบบถัดไป) ล่ม? | resilience (ทนทานต่อความผิดพลาด) | "ถ้าระบบ POS ล่ม → stock update ไหม?" | |
| 4 | data migration ต้องทำไหม? | ย้ายข้อมูลจากระบบเดิม | "ต้องย้ายข้อมูลจาก Excel 500 รายการ" | |
| 5 | backward compatibility? | ของเก่าต้องใช้ได้อยู่ไหม | "barcode เดิมต้อง scan ได้" | |

## สรุปก่อนไปต่อ

> ✅ ก่อนไป Gate 2 (Analysis) ต้องตอบได้ว่า:
> 1. ฉันเข้าใจสิ่งที่ต้องทำจริงๆ (ไม่ใช่แค่สิ่งที่ถูกสั่ง)
> 2. ฉันรู้ scope ชัดเจน + อะไรที่ไม่ทำ
> 3. ฉันรู้ constraints + edge cases
> 4. ฉันมี evidence / ตัวอย่างพอจะเริ่มวิเคราะห์
>
> ❌ ถ้าตอบไม่ได้ข้อไหน → **ถามกลับทันที ห้ามเดา**
