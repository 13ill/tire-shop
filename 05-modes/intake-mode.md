# Intake Mode — โหมดรับ Requirement
# เป้าหมาย: ถาม requirement เจาะลึก จนเข้าใจครบก่อนเริ่มทำ
# ใช้เมื่อ: ได้รับ task/req ใหม่ ต้อง clarify ให้ชัด

---

## AI ทำอะไรใน Intake Mode

1. ถามกลับ 5 คำถามพื้นฐาน (Active Reminder)
2. วิเคราะห์ requirement → ลิสต์สิ่งที่ชัด vs ไม่ชัด
3. เสนอคำถามที่ควรถาม owner
4. ช่วย refine (ทำให้ชัดขึ้น) requirement
5. ช่วยระบุ scope + out-of-scope
6. ช่วยหา edge cases

---

## Prompt สำหรับเข้า Intake Mode

```
[intake-mode]

ได้รับ requirement นี้:
"[วาง requirement ที่ได้มา]"

ช่วย:
1. สรุปว่าเข้าใจอะไร
2. ลิสต์สิ่งที่ยังไม่ชัด / คลุมเครือ
3. เสนอคำถามที่ควรถาม owner (ภาษาไทย ใช้ได้ทันที)
4. ระบุ scope + out-of-scope (เท่าที่เดาได้)
5. ลิสต์ edge cases ที่อาจถูกมองข้าม
```

---

## ตัวอย่าง

```
ผู้ใช้: [intake-mode] ลูกค้าบอก "ทำระบบจัดการ stock สินค้า"

AI:
📋 สิ่งที่เข้าใจ:
- ต้องการระบบจัดการ stock สินค้า

❓ สิ่งที่ยังไม่ชัด:
1. ธุรกิจประเภทไหน? (ร้านค้าปลีก? ร้านอาหาร? โรงงาน?)
2. สินค้ากี่ประเภท? กี่ SKU?
3. มีหลายคลัง (warehouse) ไหม?
4. ใครใช้? กี่คน?
5. ต้องเชื่อมกับระบบอะไร? (POS? บัญชี? shipping?)
6. ตอนนี้จัดการยังไง? (Excel? ระบบเดิม?)
7. ปัญหาหลักที่เจอคืออะไร?

📨 คำถามที่ควรถาม owner:
"ก่อนเริ่มทำ ขอถามเพิ่ม 5 ข้อเพื่อให้ได้งานตรงที่สุดนะครับ:
1. ร้านขายสินค้าประเภทไหนครับ? มีกี่รายการ?
2. ตอนนี้จัดการ stock ยังไง? มีปัญหาอะไร?
3. มีกี่คนที่จะใช้ระบบนี้?
4. ต้องเชื่อมกับระบบอื่นไหมครับ? (เช่น POS, บัญชี)
5. มี deadline ไหม? เพราะอะไร?"

📐 Scope (เท่าที่เดา):
- In: CRUD สินค้า, เพิ่ม/ลด stock, ดู stock คงเหลือ
- Out (น่าจะ): ระบบบัญชี, shipping, e-commerce
- ต้อง confirm กับ owner

⚠️ Edge Cases ที่อาจถูกมองข้าม:
- สินค้ามี variant (size, color) ไหม? → stock ต้องแยกตาม variant
- มีสินค้า bundle (ขายรวม) ไหม? → ตัด stock ยังไง
- stock ติดลบได้ไหม? (ขายก่อนของเข้า)
- มี barcode scan ไหม?
```
