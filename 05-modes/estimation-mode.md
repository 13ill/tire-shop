# Estimation Mode — โหมดประเมินเวลา + ราคา
# เป้าหมาย: ช่วยประเมินว่างานนี้ใช้เวลาเท่าไร ราคาเท่าไร scope แค่ไหน
# ใช้เมื่อ: ต้อง quote ราคา / ประเมินเวลาให้ owner / วาง timeline

---

## ทำไมต้องประเมิน?

```
ถ้าไม่ประเมิน:
- รับงานแล้วใช้เวลาเกิน → เสียเงิน (ถ้า fixed price)
- บอก deadline ผิด → เสียเครดิต
- scope บาน → ทำฟรีเกิน

ถ้าประเมินเป็น:
- รับงานอย่างมั่นใจ
- คิดราคาได้ถูกต้อง
- วาง timeline ที่ realistic (เป็นจริงได้)
```

---

## วิธีประเมิน: 3 ขั้นตอน

### Step 1: แบ่ง Task ย่อย

แบ่งงานเป็นชิ้นเล็กๆ ที่ประเมินได้:
```
ตัวอย่าง "ทำระบบ stock":
- Setup project: 2h
- Database schema: 1h
- CRUD Product: 3h
- Stock Movement: 3h
- Dashboard: 2h
- Auth: 2h
- Testing: 2h
- Deploy: 1h
───────────────
รวม: 16h
```

### Step 2: คูณ Buffer

```
ถ้าคุณประสบการณ์น้อย-กลาง: คูณ 1.5-2x
ถ้าระบบซับซ้อน: คูณ 2x
ถ้ามี dependency ที่ควบคุมไม่ได้: คูณ 2-3x

ตัวอย่าง: 16h × 1.5 = 24h (3 วันทำงาน)
```

### Step 3: คิดราคา

```
วิธี A: คิดจากเวลา
  ชั่วโมงละ [X] บาท × จำนวนชั่วโมง
  ตัวอย่าง: 500 บาท/ชม × 24h = 12,000 บาท

วิธี B: คิดจาก value (คุณค่าที่ลูกค้าได้)
  ระบบนี้ช่วยลูกค้าประหยัด/ทำเงินเท่าไร?
  ตัวอย่าง: ลดความเสียหาย stock ผิด 50,000 บาท/เดือน → คิด 30,000-50,000 ได้

วิธี C: คิดจากตลาด
  ระบบ stock ทั่วไปราคาเท่าไร?
  ตัวอย่าง: SaaS stock system = 1,000-5,000 บาท/เดือน
```

## Prompt สำหรับให้ AI ช่วยประเมิน

```
[estimation-mode]

ช่วยประเมินงานนี้:

งาน: [อธิบาย]
Scope: [ขอบเขต]
Tech: [technology ที่ใช้]
ความซับซ้อน: [simple/medium/complex]

ช่วย:
1. แบ่ง task ย่อย + ประเมินเวลาแต่ละ task
2. รวมเวลาทั้งหมด (รวม buffer)
3. แนะนำช่วงราคา (ต่ำ-กลาง-สูง)
4. ระบุ risk ที่อาจทำให้เกินเวลา
5. แนะนำ scope ที่ตัดได้ถ้า budget ไม่พอ
```

```
Scope ที่รวม:
- [feature 1]
- [feature 2]
- [feature 3]

Scope ที่ไม่รวม:
- [สิ่งที่ไม่ทำ]

ระยะเวลา: [X] วันทำงาน
ราคา: [X] บาท

หมายเหตุ:
- ราคารวม [revisions กี่ครั้ง]

```

## เทคนิคเพิ่มเติม

1. **อย่า underestimate** (ประเมินต่ำเกินไป) — คูณ buffer เสมอ
2. **แยก must-have vs nice-to-have** — ถ้า budget น้อย ตัด nice-to-have ออก
3. **บอก range** — "2-3 สัปดาห์" ดีกว่า "2 สัปดาห์" (เผื่อไว้)
4. **record ไว้** — หลังทำจริงเทียบกับที่ประเมิน → ปรับ accuracy ครั้งต่อไป
